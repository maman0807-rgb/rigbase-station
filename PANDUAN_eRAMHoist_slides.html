4. Reliability — Keandalan

Mengukur seberapa sering equipment mengalami kerusakan.

MTBF (Mean Time Between Failures)

MTBF = jam_jalan ÷ jumlah_kerusakan

Kategori dihitung sebagai event: breakdown troubleshoot

Bukan event (durasi saja): tunggu_spare

MTBF (jam)Status
< ½ siklus TOH🔴 Keandalan rendah
½ – 1 siklus TOH🟡 Pantau
≥ 1 siklus TOH🟢 Sehat

5. Availability — Kesiapan Equipment

Availability % = (Jam periode − Jam down) ÷ Jam periode × 100

KPI Dashboard (kartu atas)

MetricDefinisi
Availability rata-rata% uptime fleet dalam periode
Sedang DownCount event yang end_at masih NULL
MTTRMean Time To Repair — rata² lama perbaikan
MTBF (kalender)Rata² jarak antar kerusakan

Kategori Availability: 🟢 ≥95% 🟡 ≥85% 🔴 <85%

6. Workflow Catat Downtime — Hari 1 🔴

Skenario: equipment rusak, mekanik lapor segera

Aksi di app

  1. RAM → Availability → klik + Catat Downtime
  2. Isi: Equipment, Mulai Down (sekarang), Selesai (kosongkan — masih down)
  3. Penyebab: Breakdown / Troubleshoot → kotak merah 🧭 Detail Kegagalan: failure mode wajib (mis. ELU bocor oli) + komponen yang gagal
  4. Catatan: deskripsi singkat ("Engine knocking, dugaan turbo bocor")
  5. Section 📸 FOTO PENDUKUNG:
      • Fase: Sebelum / Bukti Kerusakan
      • Tgl kejadian foto: hari ini (default)
      • Caption: "Oli netes seal turbo"
      • Upload 1-5 foto kondisi rusak
  6. Simpan → toast "Upload N foto sukses"

7. Workflow Catat Downtime — Hari 3 📦

Skenario: part baru datang dari warehouse

Aksi di app

  1. RAM → Availability → list "🔴 Sedang Down" → klik Edit record
  2. Jangan ubah Mulai/Selesai (masih down)
  3. Section 📸 FOTO PENDUKUNG:
      • Fase: Part / Spare Part
      • Tgl kejadian foto: 29/05/2026 (manual, tanggal part datang)
      • Caption: "Turbo baru P/N HX35 dari gudang"
      • Upload foto part
  4. Simpan → foto ke-2 ditambah ke event yg sama, status tetap 🔴 Sedang Down
Kunci: Tgl kejadian foto bisa beda dari tgl upload → audit trail jujur kalau upload telat.

8. Workflow Catat Downtime — Hari 5 🟢

Skenario: perbaikan selesai, equipment kembali siap

Aksi di app

  1. Edit record yang sama lagi
  2. Isi Selesai = 31 Mei 2026, 17:00 + failure cause (mis. 3.4 aus wajar) — wajib saat ditutup
  3. Section 📸 FOTO PENDUKUNG:
      • Fase: Sesudah / Bukti Perbaikan
      • Tgl kejadian: hari ini
      • Caption: "Pemasangan + test run OK"
      • Upload foto after
  4. Simpan → record closed, durasi auto-terhitung 4 hari 3 jam

Tampilan di History tab

3 baris timeline terpisah:
🟢 31 Mei • SELESAI PERBAIKAN (lama 4.1 hari) — Diselesaikan oleh: David — [foto after]
📦 29 Mei • Part datang / dipasang — Oleh: David — [foto part]
🔴 27 Mei • Penyebab: Breakdown — Dilaporkan oleh: M. Yusuf — [foto before]

9. Maintainability — PM, TOH, GOH

Sistem perawatan berbasis jam (HM) untuk engine/genset/pompa, atau km untuk kendaraan.

4 Tier OEM (industry-typical)

TierEngine classPMTOHGOHEco life
ASmall <80kW (Perkins 1103A, Cummins 4BTA)5006.00012.00030.000
BMedium 80-150kW (CAT C4.4, Deutz 1013)5008.00016.00035.000
CLarge 150kW+ (FG Wilson P220, CAT DE165ED)50010.00020.00040.000
DHeavy-Duty Rig (CAT D3406/C13/C15)50010.00020.00045.000

Semua dalam jam jalan. Sisa PM = (last_pm_hours + interval) − running_hours

10. Kelayakan Armada — Maintain vs Ganti

Gabungan 2 sumbu: umur (TOH/GOH/eco_life) + keandalan (MTBF).

VerdictAturan
🟢 SehatUmur <80% AND keandalan ≥1 siklus TOH
🟡 PantauSalah satu sumbu bermasalah
🔴 Kandidat gantiUmur ≥100% AND keandalan <½ TOH

Contoh nyata (kondisi sekarang)

GS-MTU-PERKINS: running_hours 36.679 jam, eco_life 30.000 jam
→ UMUR 122% → 🔴 Kandidat ganti ✋ direkomendasikan evaluasi penggantian

11. SOP Harian Mekanik

Morning check

  1. Cek dashboard eRAMHoist
  2. Lihat kartu PM Berbasis Jam/KM — ada unit hampir lewat?
  3. Lihat Sedang Down — perlu follow up?
  4. Update HM/KM unit yg baru jalan (Logbook "Isi HM" / Edit form)

Saat equipment rusak

  1. Catat Downtime baru segera (real-time) + foto kondisi rusak + failure mode
  2. Multi-day repair: edit & update foto tiap milestone (part datang, dst)
  3. Setelah selesai: isi tanggal Selesai + foto after + failure cause

Weekly review (Sr Mekanik)

Kelayakan: cek unit 🔴/🟡 watchlist · Availability: trend MTTR/MTBF · Reliability: pattern kerusakan · 🧭 AIR: Daftar Kerja, RCA aktif, spare part Vital

Bulanan (tgl 1–12)

RAM → 📊 Laporan AIR bulan lalu: hitung KPI, isi KPI manual & SAMBAL, finalkan, kirim ke SHU ≤ tgl 12

12. Common Pitfalls (jangan terjebak)

⚠️ Edit equipment butuh login admin
RLS equipment: write admin only. Edit via Logbook gagal diam-diam tanpa error kalau bukan admin. Selalu login admin saat seed/edit data master.
📊 HM Sekarang vs HM PM Terakhir
HM Sekarang = running_hours = odometer kumulatif (bukan jam harian)
HM PM Terakhir = last_pm_hours = baseline waktu PM terakhir
Sisa PM = (last_pm + interval) − running_hours
📸 Catatan vs Caption foto
Catatan downtime = deskripsi awal kerusakan (1× per event, di Catat Downtime form)
Caption foto = mini-log per upload (multiple foto, beda phase/tanggal)

15. Strategi Pemeliharaan & Failure ISO 14224

Strategi — wizard M1–M4

M1Dampak signifikan ke K3L?Ya → M3 · Tidak → M2
M2Dampak signifikan ke produksi & biaya?Ya → M3 · Tidak → Reactive
M3Bisa dipantau & diperkirakan?Ya → CBM / Predictive
M4Ada pendekatan interval?Ya → Preventive · Tidak → Redesign

Contoh: engine Mobile Rig — produksi (M2 Ya), oli bisa dipantau SOS (M3 Ya) → CBM/Predictive.

Catat Downtime Breakdown/Troubleshoot

Failure mode — wajib saat dicatat
VIB getaran · ELU bocor oli/hidrolik · FTS tidak mau start · FTC BOP tidak menutup · OHE overheat · STD struktur retak …

Failure cause — wajib saat ditutup
3.4 aus wajar · 3.3 kesalahan pemeliharaan · 3.2 kesalahan operasi · 2.2 salah pasang · 1.2 material tidak sesuai …

+ komponen yang gagal (child equipment), jenis corrective, No. WO & notification SAP

Downtime lama → antrian "belum diklasifikasi" di dashboard AIR.

16. RCA — Aturan Pedoman AIR

🔁 Repetitive (otomatis)
3× failure mode sama pada peralatan sejenis dalam 12 bulan → RCA DRAFT dibuat sistem. Peringatan dini di 2×.
📉 LPO
Unplanned LPO. ≥ 3.000 BOPD / ≥ 30 MMSCFD / ≥ 10% produksi WK → lapor PROPAR & SKK Migas.
✍️ Manual
Atas kebutuhan fungsi.

Alur status (tombol hijau → status berikutnya, syarat dicek otomatis):

Draft → Analisis root cause → Verifikasi pejabat + aksi → Tindak Lanjut aksi SMART selesai → Monitoring efektivitas → Closed

Deteksi otomatis hanya menghitung downtime yang sudah diisi failure mode — klasifikasikan downtime lama dulu.

I — ImportantTidak ada → produksi jalan, kapasitas turunTerkait equipment Important
S — SecondaryPart pendukungLainnya / belum dipetakan
🤝 Dipinjam ≠ Habis
Stok 0 karena Peminjaman Part (belum ada stok masuk sesudahnya) tidak memicu alert Vital habis.
⏳ Usia simpan (FIFO)
Lubricant 24 · Consumable 36 · lainnya 60 bulan.
📈 Rekomendasi 2 Tahun
Pemakaian 24 bln × 24 + stok minimum − stok → Excel usulan pengadaan.
🔗 Petakan part Critical
Kelola Part Kritis → hubungkan part ke equipment, supaya kelas V/I bekerja.

18. Izin Operasi, Umur Layan & Decommissioning

📜 Izin operasi
Tab Sertifikasi: SKPI, PLO, COI, KHI, COC, Load Test, NDT. + Perpanjang → izin lama jadi riwayat. Alert H-60 & H-30 — Telegram tetap jalan.
⏳ RLA & biaya
Tab 🧭 AIR → Catat RLA: kesimpulan, batas layan baru, RLA berikutnya, tindak lanjut. Alert H-90. Biaya pemeliharaan per tahun dari Input Harian = bahan repair vs replace.
🗄️ Decommissioning
Admin. Ditolak kalau masih ada downtime/RCA/WO/reservasi/tindak lanjut terbuka atau komponen aktif. Wajib dokumen persetujuan. Data diarsip, tidak dihapus.
Tombol Hapus equipment hanya untuk salah input tanpa riwayat — unit yang punya riwayat diarahkan ke Decommission.

19. Laporan Kinerja AIR Bulanan (RAM → 📊 Laporan AIR)

  1. Pilih bulan (default bulan lalu) → 🔄 Hitung KPI otomatis: penilaian aset, vital kondisi baik, izin berlaku, Ao, MTBF, MTTR, kelengkapan failure recording, tindak lanjut RCA telat, spare part Vital habis — per akhir bulan.
  2. Isi KPI manual: anggaran, pembenahan SAP, PM sesuai jadwal, insiden keselamatan & lingkungan.
  3. KPI ❌ tidak tercapai → SAMBAL: Siapa · Apa · Mengapa · Bagaimana · Aksi Lanjut (wajib lengkap).
  4. ✅ Finalkan (angka terkunci) → 🖨 Cetak berkop / 📊 Excel → kirim ke SHU paling lambat tanggal 12.

Pengingat muncul di Daftar Kerja & Dashboard sampai laporan bulan lalu final (merah kalau terlambat). Target KPI = usulan, admin ubah lewat ⚙️ Target KPI.
